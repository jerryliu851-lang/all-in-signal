# DECISIONS

One line per judgment call that the brief did not specify. Append; never rewrite history.

- 2026-11-07 Poller uses `yt-dlp` flat-playlist listing, not RSS: YouTube's Atom feed (`/feeds/videos.xml?channel_id=`) returned 404 for every channel tested, including a control channel. RSS is still tried first as an optional fast path and ignored on any non-200.
- 2026-11-07 "Full episode" = member of the channel's **All-In Podcast** playlist (`PLn5MTSAqaf8peDZQ57QkJBzewJU1aUokl`) AND duration >= 45 min; legacy `E###` titles are also accepted. Current titles no longer carry `E###`, and the 25-55 min interview videos are not in that playlist.
- 2026-11-07 Analysis backend is the Claude Code CLI in print mode with `--json-schema` structured output, authenticated with Jerry's Max subscription (`CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`), not the Anthropic SDK + API key. Model pinned to `claude-opus-5-5`. The backend sits behind `allin.llm.LLMBackend`, so an SDK backend is a one-file addition.
- 2026-11-07 Storage = committed JSON under `data/` behind `allin.store.Store`. Chosen over SQLite because JSON diffs and merges in git and is served directly by GitHub Pages; the interface keeps a Supabase swap to one module.
- 2026-11-07 Single-pass analysis when the transcript is under 120k estimated tokens (every All-In roundtable so far is ~25-35k); chunk + consolidate only above the threshold.
- 2026-11-07 Opus 5.5 at low effort also judges Polymarket matches. Unmatched candidates are retried at most every 7 days and only when the Gamma search surfaces market ids not judged before, so idle runs make zero LLM calls.
- 2026-11-07 Repo is public (free GitHub plan requires public for Pages). Normalized transcripts are committed and therefore public.
- 2026-11-07 Scorecard counts only `stance_type == own_view` predictions. Reported views and devil's-advocate items stay in the ledger but are excluded from accuracy.
- 2026-11-07 Cost is reported as token counts plus "API-equivalent USD" from the CLI envelope (`total_cost_usd`). With the Max token the real cost is subscription quota, not dollars.
- 2026-11-07 Dashboard uses liquid-glass styling per the brief, overriding the maintainer's usual no-glassmorphism default.
- 2026-11-07 Prediction ids are `<video_id>-p<nn>` (zero-padded, order of appearance) so they are stable across re-runs of the same episode and human-readable in `resolutions.yml`.
- 2026-11-08 RSS turned out to be flaky rather than dead (404 on every 2026-11-07 probe, 200 on 2026-11-08). It stays an optional fast path; its ids are only used when no `--limit`/backfill is given, are tagged not-in-playlist, and an exclusion for that reason is re-evaluated once the video shows up in the playlist listing.
- 2026-11-08 Episode classification order: live/upcoming -> unknown duration -> 45-minute floor -> playlist membership or legacy `E###` title; exclusion reasons are specific strings such as `duration_2400s_below_2700s_floor`.
- 2026-11-08 Backfill lists `max(limit*3, listing_limit)` playlist entries and transcribes only the newest `limit` full episodes; older discovered episodes are left alone.
- 2026-11-08 Transcript track preference: manual `en`, then generated `en`, then any `en-*`; the yt-dlp fallback reads json3 from `subtitles` then `automatic_captions`. After a failure the episode is retried every run until `max_transcript_attempts`, then once more every 7 days; never silently skipped.
- 2026-11-08 Normalization strips bracketed cue tags, decodes HTML entities (repeatedly), breaks paragraphs at a sentence end once past 60 words, and hard-caps paragraphs at 45 s / 120 words. Every word is kept so quotes can be string-matched later.
- 2026-11-08 A judged Polymarket match stores `polarity` (same/inverse); `market_yes_probability` and divergence are expressed in the hosts' question frame, and resolution maps a market's No to the hosts' yes when polarity is inverse.
- 2026-11-08 Gamma or model failures during matching never create an unmatched record; the candidate is skipped and retried next run. The judge may only pick from the market ids it was shown; anything else counts as no match.
- 2026-11-08 Manual entries in `resolutions.yml` always override Polymarket and any earlier status and are re-applied on every run (idempotent). A passed timeframe never auto-resolves; the ledger flags it `timeframe_passed`. Polymarket outcomes other than Yes/No leave the prediction pending with a note. Accuracy = correct / (correct + incorrect), 3 decimals, None when nothing resolved; unresolvable is excluded from the denominator.
- 2026-11-08 Pipeline deploys Pages only when `data/` changed (or on manual dispatch); the backfill workflow defaults to `estimate` mode and `run` is a separate dispatch after the owner reviews the estimate. Workflow inputs reach the shell through env vars with a numeric check, never `${{ }}` interpolation. Data commits use a 3-attempt `pull --rebase` retry and one shared concurrency group.
- 2026-11-08 Site build derives `predictions.json` by calling `allin.scoring.ledger.build_ledger` when the store has no ledger yet, so an analyze-only run still fills the ledger view and the rules have one home.
- 2026-11-08 `manifest.json` carries host names, colour keys and `divergence_flag_points`, so the static page never hard-codes settings. `build_site` only deletes an output folder inside the repo or the system temp dir, never `site/`, `data/` or `src/`.
- 2026-11-08 Stock "net stance" = sum of +1 bullish / -1 bearish / 0 neutral over every call; a call naming several tickers counts once per ticker. Dashboard uses no animation library; motion is CSS-only and off under prefers-reduced-motion.
- 2026-11-08 Quote verification: a quote also counts as verified when its words match the transcript with punctuation ignored (auto-caption punctuation is noisy); near-match ("flagged") checks are skipped under 15 characters and search +/-180 s around the model's timestamp first. Speaker names, theme labels and tickers are normalised in code (full host names, "Guest:" prefix, lowercase themes, uppercase tickers).
- 2026-11-08 Chunk windows start the next chunk at the first paragraph within `chunk_overlap_seconds` of the previous end, always advancing at least one paragraph; the chunked estimate assumes each chunk and the merge call each produce a full episode's output.
- 2026-11-08 `JsonFileStore` skips a write when the only differences are volatile timestamps (`updated_at`, `seen_at`, `last_checked_at`), so idle runs leave `data/` byte-identical and therefore commit nothing and deploy nothing.
- 2026-11-08 `allin analyze` skips episodes that already have an analysis unless `--force`; prediction ids follow the model's output order, so a forced re-run drops that episode's Polymarket bookkeeping (pruned automatically) and may orphan `resolutions.yml` entries (reported as warnings).
- 2026-11-08 The Analyze step runs whenever episodes are awaiting analysis (`pending_analysis` output), not only when this run found new ones, so a failed analysis retries on the next tick; Resolve/Build/Commit run even after a failed analysis so fetched transcripts are saved.
- 2026-11-08 Only markets whose outcomes are exactly Yes/No are shown to the match judge; out-of-range implied probabilities from the model become null instead of producing absurd divergences.
- 2026-11-08 Exclusions for `live_or_upcoming` / `duration_unknown` are temporary and re-checked every listing; a judge verdict with match=true but polarity `n/a` counts as no match; a manual resolution without `resolved_on` keeps the date it was first applied; scoring's Polymarket fallback uses the same polarity rule as the matcher.
- 2026-11-08 The structured-output schema carries no `$schema` key: the Claude Code CLI's validator rejects the 2020-12 meta-schema URI. `allin backfill --count N` analyzes at most the newest N transcribed episodes, so a backfill can be split across runs (`count=5`, then `count=10`).
- 2026-11-08 First real run (2026-11-07 episode): 49/49 quotes verified, 34 predictions, 33 of them with `attribution_confidence: high`. Attribution may be optimistic without speaker labels; the scorecard and ledger expose the confidence so readers can discount it, and the prompt is the place to tune it (`prompts/analyze_episode.md`).
- 2026-11-08 Gamma's `public-search` handles full sentences badly (the Brent-crude question returned baseball markets) and short keyword queries well ("Anthropic IPO" -> 52 relevant markets). The analysis model now emits 2-4 `search_keywords` per candidate; the matcher searches those first, then a short entity/number query, then the de-stopworded and full question, ranks the Yes/No results by keyword overlap and shows the judge the top 12. Unmatched records keep the judge's last rationale.
- 2026-11-08 `allin match` uses a lazy backend: idle cron ticks with nothing to judge need no credentials (so Pages can deploy data-only changes), while a run that must judge still fails loudly on its first model call if the token is missing. `allin analyze` keeps the eager check.
- 2026-11-08 Verified from a real Actions runner: YouTube blocks caption fetches (youtube-transcript-api `RequestBlocked`, yt-dlp sees no caption track) while playlist listing, Gamma, Claude Code and deno work. Remedies documented in the README: an `ALLIN_YT_PROXY` secret (residential/rotating proxy) or fetching captions locally and pushing the transcripts; the backfill transcripts were fetched locally.
- 2026-11-08 Forward-only cron: the playlist listing is newest-first, so ingestion stops considering playlist entries once it reaches the newest episode already tracked. The first cron tick had reached back past the 10-episode backfill and registered older episodes as transcript_unavailable; the merge kept the local backfill index and discarded those entries.
- 2026-11-08 Third transcript fallback: when YouTube blocks the runner, metadata comes from the libsyn podcast feed and the transcript from the episode mp3 transcribed with faster-whisper (`small.en`, int8, CPU). A YouTube episode is matched to a feed item by duration within 5 s (best title `token_set_ratio` breaks ties), else a title-only match of at least 90, else no match. The cuts are identical, so timestamps align; quotes are verified against the Whisper text. We decode audio with PyAV directly because faster-whisper 1.2.1 passes an `av.open` kwarg (`metadata_errors`) that current PyAV rejects.
- 2026-11-08 The `whisper` extra pins `av<19` because PyAV 19 removed the `metadata_errors` kwarg faster-whisper 1.2.1 passes; `whisper_transcribe.py` additionally decodes with PyAV itself so a future faster-whisper/PyAV mismatch cannot break transcription. Measured on a runner: `base.en` RTF 0.03, `small.en` RTF 0.08 (default `small.en`).
- 2026-11-08 Proven on a GitHub-hosted runner end to end: newest episode ingested with YouTube fully blocked (metadata from the podcast feed, 133 MB mp3 from libsyn, `small.en` transcription of 93 min in ~14 min, RTF 0.15, 16,704 words). The cron is therefore autonomous without a proxy; only the Max token secret is needed for analysis.
- 2026-11-09 Measured the attribution labels of the 10-episode backfill before changing anything: 218 of 272 predictions were `high` (80%), yet a name of the attributed host (any known spelling) appears within 2 minutes of the claim for only 36% of those, and within 4 minutes for 56%. The label was not backed by anything a reader could check.
- 2026-11-09 Attribution is now evidence-backed like quotes. The model returns `attribution_basis` (named_handoff, addressed_by_name, self_reference, segment_role, guest_intro, indirect, topic_or_style, none) and `attribution_evidence` (the verbatim cue) before `attribution_confidence`, for key takes, predictions and stock implications. `allin.analyze.attribution` string-matches the cue and only ever lowers the label: `high` needs a strong basis plus a cue found verbatim inside the window; a missing, near-match, out-of-window or own-quote cue caps at `medium`; `indirect` caps at `medium`; `topic_or_style`, `none` and speaker `Unknown` cap at `low`; a cue that is not in the transcript is deleted.
- 2026-11-09 The cue window is 480 s before to 120 s after the item. Measured from the `>>` markers of the backfill captions: 2,789 speaker turns, median 5 s, p99 198 s, longest 443 s, so a handoff that still governs a claim is never more than about 8 minutes back.
- 2026-11-09 The code does not require a name-based cue to contain the host's name. In the validation run a regex over the known spellings found the name in only 16 of 42 handoff/reply cues, all of which a reader would accept ("Chimath", "Chimat", "Saxs", "Jal", "Math, go ahead"); enforcing it would downgrade correct attributions.
- 2026-11-09 Validation of the new prompt and check (2026-11-07 episode, same caption transcript, scratch store, live data untouched): `high` went from 57 of 58 items to 33 of 59; 57 of 58 cited cues verified in window and the code had to downgrade 1 item (the prompt does the calibrating, the check is the backstop); the speaker was identical on all 26 predictions that could be paired old-to-new; 35 predictions vs 34; quotes 50 of 50 verified. Cost per episode rose: 40.9k output tokens vs 28.9k, 333 s vs 236 s, $1.15 vs $0.89 API-equivalent. Polymarket candidates were 4 vs 7, inside the 2 to 9 spread of the backfill episodes, and the one candidate with a live market match appears in both.
- 2026-11-09 The 10 backfilled episodes were not re-analyzed (owner's call: about $10 API-equivalent of Max quota, and a forced re-run renumbers prediction ids and re-judges the Polymarket matches). Their items keep the old labels with null basis/evidence and the dashboard tooltip says "Not cue-checked". `schema_version` stays "1" because the new fields are additive; the ledger gains three keys per prediction on the next resolve.
- 2026-11-09 The analysis prompt now describes the transcript it is given (`transcript_notes`): YouTube captions have `>>` speaker-change markers, Whisper transcripts from the podcast fallback have none, and the old wording told the model to rely on markers that are absent on every runner-ingested episode.
- 2026-11-09 The podcast-Whisper path now sends a glossary (`hotwords`: the four hosts, "J-Cal", "All-In Podcast", "Polymarket") by default; `ALLIN_WHISPER_HOTWORDS=off` disables it. Measured on GitHub-hosted runners, same 2026-11-07 episode, `small.en` int8 greedy, about 11 minutes end to end either way (probe-sources runs 42751780085 without and 42751791894 with): without the glossary the text drifts within minutes into lowercase, unpunctuated output with numbers spelled out ("dames will have at least two hundred fifty seats") and stays there; of the 49 quotes verified against the YouTube captions only 26 appear verbatim (9 near, 14 missing), caption 5-gram agreement is 69.6%, and "Sacks" is spelled right once against 10 misspellings. With the glossary: 41 verbatim, 8 near, 0 missing; 82.9% agreement (higher in every 5-minute bucket, no dropped speech); Sacks 15 right and 2 wrong, Friedberg 15 and 0, Chamath 24 and 0. The glossary is applied to every decoding window, so it also anchors punctuation and casing, which `initial_prompt` (first window only) would not.
- 2026-11-09 Known cost of the glossary: it can insert a name. Of 70 glossary-word occurrences in that transcript, 69 are corroborated by the glossary-free run or the captions (often as a garbled form: "shimab point", "jc out", "polyhappet"); 1, a trailing ", Chamath.", appears in neither. The glossary is kept short for that reason.
- 2026-11-09 The path the cron will take for a new episode was validated before the token secret exists: the runner's `small.en` + glossary transcript was analyzed locally in a scratch store with the new prompt. 15 takes, 29 predictions, quotes 44 of 44 verified, cited cues 51 of 51 verified, labels 20 high / 31 medium / 1 low (more cautious than the 33 / 25 / 1 from captions, which have `>>` turn markers). The speaker matched the caption-based analysis on 27 of 28 paired predictions; the other is the same low-confidence item (Sacks vs Unknown). One interpretive difference: "a dark cloud over Anthropic's IPO and of course after that OpenAI's ... a 71% chance of going public" was read as OpenAI from the Whisper text and as Anthropic from the captions, although both transcripts carry the same words.
- 2026-11-09 The cost estimator assumed 12,000 output tokens per episode; measured output including thinking was 28,926 before the attribution fields and 36,349 / 40,879 after. `est_output_tokens_per_episode` is now 38,000, which puts the estimate at about $0.88 per episode against measured $1.01 and $1.15 (the remaining gap is the schema, the CLI's scaffolding and cache-write pricing, stated in the estimate's note). Re-analyzing all 10 backfilled episodes estimates at $8.79, so expect roughly $10.50 API-equivalent before matching.
- 2026-11-09 Default Whisper model stays `small.en` (with the glossary). `medium.en` measured on runners on the same episode: plain, 20 minutes end to end (rtf 0.22), 41 of 49 caption-verified quotes verbatim, 7 near, 1 missing, 83.3% caption 5-gram agreement, hosts spelled right about half the time (Sacks 8 right / 7 wrong, Friedberg 4 / 5); with the glossary, 39 minutes (rtf 0.42), 37 verbatim, 7 near, 5 missing, 85.8% agreement, and worse names than `small.en` with the glossary (Sacks 3 / 9, Friedberg 4 / 11 against 15 / 2 and 15 / 0). One run per configuration on one episode, so small differences are noise; the size of the gap between plain `small.en` and everything else is not (probe-sources runs 42751802365 and 42754005062).
- 2026-11-09 `.gitignore` now also covers `.env.*` (keeping `.env.example`), `secrets/`, `*.pem` and `*.key`, and `.env.example` shows its non-secret defaults as comments so that no variable in a tracked file carries a value. No secret has ever been committed here; the token is set only with `gh secret set` by the owner.
- 2026-11-09 A forced re-analysis now explicitly forgets that episode's Polymarket matches and unmatched records (`forget_market_bookkeeping`). The earlier pruning only removed prediction ids that no longer existed at all; since a re-run renumbers ids, an old match would have stayed attached to whichever different prediction inherited its id, and `resolve` would then have marked that other claim correct or incorrect from a closed market. Found by reading the match and resolve code before re-analyzing the backfill; `runs.json` shows no forced re-run had ever been made on live data.
- 2026-11-10 The 10 backfilled episodes were re-analyzed under the evidence-backed attribution on the owner's go-ahead (`allin analyze --force`, one run on 2026-11-09 that hit the Max 5-hour limit after the first episode, the other nine the next day; a failed episode keeps its old analysis, so nothing was left half-written). Measured: predictions 272 -> 260, key takes 154 -> 149, stock implications 84 -> 71; `high` attribution on predictions 218 (80%) -> 128 (49%), medium 45 -> 108, low 9 -> 24; quotes 409 of 409 verified; 425 of 444 cited cues verified in window; the code check downgraded 5 items in total. Cost $10.54 API-equivalent and 50 minutes of model time, against the $8.79 estimate plus its stated 20%.
- 2026-11-10 After the re-analysis every one of the 22 previously matched claims was still present (paired by identical verbatim quote and timestamp; one by wording). 20 had been re-emitted as candidates; the Russia-Ukraine ceasefire candidate was copied over from the old analysis so the judge could re-evaluate it. One was deliberately not carried: Sacks's "a normal out-party gain rather than a Democratic tsunami" had been resolved correct from the "Democrats control the House" market, which does not test the "rather than a tsunami" half; it is now pending and needs a manual entry in `resolutions.yml` if it is to be scored. All 46 candidates were then judged from scratch: 26 matches (was 22), 20 unmatched, 10 resolved predictions (was 7: 6 correct, 4 incorrect), each resolution reviewed by hand against its market.
